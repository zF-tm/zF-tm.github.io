# How WPS Works

## The Big Picture

WPS connects devices by sending a series of back-and-forth messages (called EAP messages). During this process, the router and device share things like:

- Public keys
- PINs
- Random secret numbers (called "nonces")

At the end, if everything checks out, the router shares the **real WiFi password (PSK)** with the device — and normal WiFi communication begins.

**Fun fact:** The "roles" can actually swap. Usually the router is the one sharing settings (called the "Registrar"), and the device receiving them is the "Enrollee." But sometimes it's reversed — a device can configure the router instead.

---

## How WPS Gets Started

There are a few ways this whole process kicks off:

- **PIN method** — started by the client (device)
- **Push button method** — started manually on the router
- **NFC method** — using tap-to-connect tech (RFID-based)

---

## The WPS PIN: Why It's Weak

The WPS PIN is **8 digits long**, split into two halves:

- **First half** (4 digits) — used in messages M4 and M5
- **Second half** (4 digits) — used in messages M6 and M7

You'd think 8 digits means 100,000,000 possible combinations. **Not true.** There are only **11,000** possible combinations.


![Pasted image 20260917224907](/images/notes/wifi/introduction-to-wps/pasted-image-20260917224907.png)


**Why so few?**

- The first half only has 10,000 possible combinations (4 digits = 10⁴)
- The second half only has 1,000 real combinations (not 10,000) — because its _last digit_ is just a checksum (a calculated confirmation digit, not a real guess)

Add those together: **10,000 + 1,000 = 11,000 total combinations.**

That's a tiny number for a computer to guess through.

## Key Terms You'll See

Before diving into the message sequence, here's a quick glossary:

|Term|Simple Meaning|
|---|---|
|**PKe**|The router's public key (used for secure key exchange)|
|**PKr**|The device's public key|
|**PSK1**|First half of the PIN (10,000 possible values)|
|**PSK2**|Second half of the PIN (1,000 possible values; last digit is a checksum)|
|**KDK**|A key used to help build the "Auth Key"|
|**KWK**|A key used to encrypt messages|
|**E-S1 / E-S2**|Secret random numbers generated by the router|
|**R-S1 / R-S2**|Secret random numbers generated by the device|
|**E-Hash1 / E-Hash2**|Special codes built from the router's secret numbers + PIN halves — used to verify things|
|**R-Hash1 / R-Hash2**|Same idea, but built from the device's side|
|**Auth Key**|A combined key built from KDK + both PIN halves|
|**WPA-PSK**|The actual WiFi password — the end goal|

## The Message Sequence (Step by Step)

Here's what happens, message by message:

| Message                   | What Happens                                                                                                  |
| ------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **EAPOL-Start**           | The device says "let's begin"                                                                                 |
| **EAP Request Identity**  | Router asks: "who are you?"                                                                                   |
| **EAP Response Identity** | Device answers with its identity                                                                              |
| **M1**                    | Router sends its public key                                                                                   |
| **M2**                    | Device sends its public key back                                                                              |
| **M3**                    | Router sends two special hash values (E-Hash1, E-Hash2)                                                       |
| **M4**                    | Device sends its own hash values, plus a secret number, encrypted                                             |
| **M5**                    | Router sends one of its secret numbers, encrypted                                                             |
| **M6**                    | Device sends its second secret number, encrypted                                                              |
| **M7**                    | If the PIN was correct, the router sends its second secret number **and the actual WiFi password**, encrypted |
| **M8**                    | Device confirms by sending the password back — normal WiFi connection begins                                  |

---

## Why This Matters for Cracking

Because there are only 11,000 possible PIN combinations (not millions), and because parts of the process leak useful clues, attackers can use two main approaches to guess the PIN and steal the WiFi password:

1. **Online brute-forcing** — repeatedly trying PINs directly against the router (slower)
2. **Offline brute-forcing (aka "Pixie Dust Attack")** — using leaked data to guess the PIN without even touching the router live (much faster)
